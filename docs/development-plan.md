# 星屿应用端开发规划

更新日期：2026 年 10 月 29 日。代码基线：`acabcb6`。开发者：你与 Codex。

本阶段按“星屿次元聚集地产品架构展示板”建设用户端、画师端、漫展方端、商家端四个小程序的页面和交互演示。你已确认仅做四个小程序，图中的 Web 管理界面和后端服务不纳入本阶段。

按你每天投入 2–3 小时、每周 5 天，我承担主要实现和验证，预计 **四个小程序需要 15–20 个有效协作日，约 3–4 周**，已包含视觉调整与缺陷修复缓冲。

本规划替代此前 6–8 周的真实交易 MVP 排期。交付目标为可操作、可讲解的应用端演示；真实登录、收款、后端业务和跨端实时同步在后续接入阶段另行评估。

## 四 数据和演示流程

页面通过独立的数据适配层访问商品、作品、画师、活动、票种、购物车、订单、报名和审核数据，后续接服务时替换适配器。

| 演示流程 | 连续操作 |
| --- | --- |
| 购买周边 | 搜索 → 商品详情 → 加购物车 → 选择地址 → 本地下单 → 模拟支付 → 订单详情 |
| 画师约稿 | 作品 → 画师主页 → 约稿表单 → 本地需求记录；画师端另有匹配的接单样例 |
| 漫展购票 | 查找活动 → 选票 → 填报名信息 → 模拟购票 → 电子票；主办方端有对应核销样例 |
| 商家经营 | 编辑商品 → 用户端同步显示 → 用户模拟支付 → 商家发货 → 用户确认收货 → 两端订单完成；退款后续实现 |

同一端使用统一状态源，操作后立即更新列表和详情；必要数据在重启后恢复，并提供一键重置演示数据。模拟支付确认页明确使用“模拟支付”，不会发起真实扣款。演示身份与本地状态不作为服务端权限能力。

用户端与商家端现通过同一个本地模拟服务共享商品、库存、店铺与订单，每 1.5 秒同步一次前台状态，数据保存在项目 `.tools/demo/marketplace.json`。收藏、购物车和虚构收货地址仍按端存储。画师端与漫展方端后续按各自流程接入；演示角色用于区分操作，不代表真实身份认证。普通现货快递流程先行，退款、预售、定金与线下自提暂不纳入本轮。

模拟请求包含加载、空数据、失败重试和表单校验。图片临时路径不直接视为永久存储；需要重启保留的图片采用可持久化方案或固定演示素材，并在对应平台验收。

## 八 验收标准

- 四端与参考图的品牌风格、信息层级和角色定位一致；移动端适配约 375/390/430px 宽度、安全区、长标题和空状态。
- 主要入口、返回、标签、筛选、列表详情、表单和确认弹窗可操作，结果有明确反馈。
- 收藏、购物车、地址、订单及报名在本端正确更新；必要数据重启可恢复；重置后回到确定的演示场景。
- 商品选择与订单金额一致，模拟支付成功/取消/失败和退款场景可演示，实际不调用支付扣款。
- 作品编辑、活动票种配置、商品上下架、发货等各有可完整验证的本地流程。
- 核销包含首次成功和重复提示；表单覆盖必填、数量及格式校验。
- 演示模式下 H5 需要启动轻量本地模拟服务，无需启动正式后端、MySQL 或 Redis；小程序构建通过，并按可用开发者工具及真机条件记录验收范围。
- TypeScript 和交付端构建通过；关键状态逻辑、恢复行为与主要操作路径完成回归。
- 文档、启动命令、演示脚本与代码一致，标明已实现、本地模拟及后续服务接入的范围。
