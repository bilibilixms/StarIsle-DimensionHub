## 交易闭环

浏览器使用独立商家、用户账号完成以下连续操作：

1. 商家注册并输入演示资质验证码，从空店铺发布售价 29 元、库存 2 件的商品。
2. 用户注册，搜索商品名称，进入详情并加入购物车。
3. 从购物车结算，新增收货地址并核对商品和金额。
4. 在支付请求尚未完成时双击模拟支付，确认只发出一次支付命令、生成一笔订单、库存变为 1 件。
5. 商家查看本店订单并填写演示物流单号发货，用户端同步显示待收货及物流。
6. 用户确认收货，两端显示同一订单已完成。
7. 两端刷新后仍保留完成状态，购物车中的已购商品已移除，服务端仍只有一笔订单。

对应回归用例位于 `tests/e2e/auth.spec.ts`，补强了原有新商家发布与订单隔离用例。已有双端交易用例继续验证内置演示账号的联动。

## 异常与恢复

| 场景                       | 验收结果                                                           |
| -------------------------- | ------------------------------------------------------------------ |
| 库存不足、最后一件并发购买 | 拒绝超量购买，不超卖；失败时不部分扣库存或创建订单                 |
| 同商品不同规格             | 合计数量校验库存，同店多商品及规格合为一单                         |
| 跨店购买                   | 按店铺拆单，整次购买校验通过后统一提交，分别发货                   |
| 双击支付、重复请求         | 支付过程中阻止重复提交；重试保留原操作标识                         |
| 支付已成功但响应丢失       | 刷新后可确认原结果，不重复生成订单或扣库存                         |
| 支付响应丢失后商品下架     | 已提交订单可恢复原结果，未提交订单显示下架提示                     |
| 断网与重连                 | 显示连接失败和重试入口，写操作不回退为单端假成功；重连后可继续购买 |
| 商家改价、编辑期间售出库存 | 购买需重新确认价格；仅改价不覆盖已售库存，过期库存编辑被拒绝       |
| 切换账号、游客及撤销登录   | 本机购物车、收藏及确认单按账号隔离；订单和店铺写入受身份、归属限制 |
| 服务重启                   | 商品、库存、订单、账号、会话和幂等记录恢复，重试不重复扣库存       |
| 地址修改、删除与默认地址   | 本次选址与默认地址分离；已付款订单保留原收货快照                   |
| 商品及店铺资料变化         | 已生成订单保留交易时的商品、价格和店铺快照                         |
| 共享场景重置               | 清理不存在商品对应的购物车记录；旧支付操作失效并要求重新确认       |

浏览器回归包含 375、390、430px 宽度下的样板及关键页面布局检查，未发现横向溢出。
