# StarIsle-DimensionHub

星屿｜次元聚集地。面向用户、画师、漫展方和商家的二次元社区与交易产品。

当前应用采用一个小程序统一入口，用户和商家可注册登录；管理员入口和工作台暂时隐藏，留到最后考虑，画师和漫展方保留选项，暂未开放。用户首页、商品详情和商家工作台已通过本地模拟服务打通“上架 → 模拟支付 → 发货 → 确认收货”。原有 user-miniapp、merchant-miniapp 两个构建目标保留，均提供同一套完整页面，方便现有开发者工具项目继续预览。

## 快速预览应用端

需要 Node.js 22.23.4 / npm 10。已有项目内工具链时脚本会自动使用 `.tools/node`；工具安装方式见下方。

```bash
./scripts/npm.sh ci

# 三个终端分别执行；无需启动 Java 后端、MySQL 或 Redis
./scripts/npm.sh run dev:demo
CI=true ./scripts/npm.sh run dev:user:h5
CI=true ./scripts/npm.sh run dev:merchant:h5
```

- 用户端：http://localhost:5173
- 商家端：http://localhost:5174
- 商品详情：在用户首页点击商品卡片。

首页搜索支持商品名、店铺名和商品标签，忽略关键词两端空格及英文字母大小写。商品最多设置 10 个标签，每个最多 12 字，自动去除前缀 #、重复标签和多余空格。输入普通关键词可匹配标签，输入 `#原神` 或点击商品卡片、详情页和店铺商品的标签时，精确查找具有相同标签的已上架商品；标签搜索不混入名称相似的商品或店铺。标签查询链接支持刷新恢复，原有单标签商品保持兼容。搜到店铺时会展示可点击的店铺卡片及该店上架商品；店铺页展示店铺名称、介绍和本店已上架商品。商品详情「进店逛逛」也进入同一店铺页。游客可以搜索、浏览店铺和商品，购买及收藏时仍需登录。

商家「发布新品」支持最多 6 张商品图片、设置封面、周边/画作分类、简介、标签与详情，以及最多 12 个自定义规格。每个规格分别填写名称、价格和库存；用户商品页可滑动查看图片、选择规格，购物车、确认订单和历史订单保留对应款式及成交价格。商品列表显示最低规格价格，总库存为各规格库存之和。可选择发布后立即上架，或先保存为下架商品。已有商品默认保留标准版/礼盒版共用库存，编辑时可启用自定义规格并重新分配库存。

图片支持 JPG、PNG、WebP 静态图片，每张不超过 2 MB，上传后由本地服务压缩保存到 `.tools/demo/uploads/`，重启仍可访问；商品记录与图片目录一起构成演示数据。商家只能使用本店上传的图片。仅改价格或资料时保留最新销售库存，主动调整库存会校验编辑时的原库存；商品资料被其他操作修改时要求重新打开编辑。规格删除后购物车会提示重新选择并阻止下单，原订单保留购买时的规格名称、价格及图片。

商品可额外上传 1 个可选视频，支持 MP4（H.264）、最长 60 秒、最大 20 MB。商家发布和编辑时可预览、更换或移除，第一张图片仍作为封面；用户详情页提供独立播放器，点击后播放，不自动播放。视频与演示数据一并保存在 `.tools/demo/uploads/`，重启后保留；服务验证上传大小、视频轨道及片段时长，并提供 HTTP Range 分段读取。视频仅可绑定到上传商家自己的商品，当前不做自动转码。

首次打开进入身份选择和注册登录页。选择用户或商家后，可一键登录对应的本地演示账号：用户 `13800000000`、商家 `13800000009`。商家快速登录会使用该账号已有的店铺；全新演示数据会在首次商家登录时创建可营业的空店铺。注册时，手机号只校验 `1` 开头的 11 位数字，密码至少 6 位（最多 128 位），用户校验通过即可注册并登录，不发送短信。商家注册分为填写信息、演示资质验证两步，可选填店铺名称；输入页面显示的固定验证码 `1234` 后提交入驻申请并进入待审核工作台，管理员通过后才能上架商品。驳回原因会显示给商家，可修改店铺资料后重新提交。同一手机号使用原密码可同时开通用户和商家，新增商家身份同样需要入驻审核。

管理员界面当前关闭：身份选择不展示管理员，旧管理员登录链接返回用户登录，旧工作台链接也返回登录页，已有管理员会话不会自动进入工作台。开关位于 `packages/shared/src/features.ts` 的 `ADMIN_UI_ENABLED`，已有管理组件、接口及数据保留，待后续启用。以下管理规则为预留实现，商家审核及现有交易规则不因界面隐藏而变更。

管理员禁用账号后，该账号的所有会话立即撤销，恢复后需重新登录；所属店铺商品也暂停展示。暂停店铺或管理员下架商品后，用户端同步停止展示和新购买，商家工作台显示状态与原因。恢复商品展示保留商家原来的上下架选择。暂停店铺仍可处理已付款订单的发货，用户仍可确认收货，订单保留原始商品、金额及地址快照。商家自行上下架、编辑或重置演示数据不能解除管理员下架限制。管理请求支持幂等重试，数据发生变化时要求刷新后重新处理。

用户可选择「先逛逛」浏览和搜索商品，收藏、购物车、下单及订单详情需要登录；商家没有游客工作台。个人中心支持切换身份、退出登录。各用户的本机购物车、收藏、地址和待确认支付操作分别保存，订单按账号隔离；新商家拥有自己的空店铺，不能操作其他店铺的商品、订单或重置其数据。账号和会话保存在本地演示服务，密码以带随机盐的摘要保存。这是开发演示账号体系，手机号未验证归属。

商品、库存、店铺、订单及演示账号统一保存在 `.tools/demo/marketplace.json`，服务重启后仍会恢复；前台每 1.5 秒自动同步。用户「我的」可管理多个演示收货地址、设置默认地址；商品立即购买和购物车结算进入独立确认订单页，选择本次地址、核对分店商品和金额后模拟支付。同店多件商品合为一笔订单，跨店分别生成订单并独立发货；点击订单卡片查看完整商品清单和交易快照；商家「我的」可重置本店演示数据。待发货订单支持仅退款；待收货、已完成订单（含历史订单）支持整单仅退款或退货退款。仅退款由商家审核，已发货订单退款不自动回补库存；退货退款需商家审核并填写退货地址，用户提交寄回物流后，由商家确认收到退货再完成退款，可选择商品是否重新入库。审核中或尚未寄回时可撤销；拒绝、撤销均恢复申请前订单状态，历次申请留存。售后处理中暂停发货及确认收货，完成退款后从成交额中扣除。重复处理不会重复回补库存，已删除规格不会回补到其他规格。当前无售后期限限制，暂不支持部分退款、自动超时处理、平台介入和真实资金退款。微信授权、短信验证、真实支付及物流尚未接入，「模拟支付」不会扣款。服务断开时页面显示提示，注册、支付和发货不会回退为单端假成功。

视觉样板的操作路径、验证范围和素材说明见 [视觉样板说明](docs/visual-samples.md)。

用户订单卡片右下角提供评价和售后快捷按钮，按状态显示「去评价／查看评价」「申请售后／售后进度／退款详情」，打开后优先展示对应操作区域。用户确认收货后，可在订单详情按购买款式发布评价，支持 1–5 星评分、最多 500 字文字和 3 张图片（每张不超过 2 MB）。同一订单款式只能评价一次，重复购买可分别评价；旧订单也支持。商家工作台「评价管理」可查看全部或待回复评价，每条允许发布一次最多 500 字的公开回复。商品详情展示平均评分、买家评价及商家回复，买家昵称遮挡展示，公开结果不含订单号或买家账号 ID。退款不删除原有评价，并标记交易已退款；商家重置本店演示数据会清理本店评价。当前评价和回复发布后不可修改，尚未加入追评、举报与平台审核。

## 微信小程序预览与构建

```bash
# 先启动共享演示服务，再分别持续构建两个小程序
./scripts/npm.sh run dev:demo
CI=true ./scripts/npm.sh run dev:user
CI=true ./scripts/npm.sh run dev:merchant

# 验证与发布构建
./scripts/npm.sh run typecheck
CI=true ./scripts/npm.sh run build
CI=true ./scripts/npm.sh run build:h5
```

微信开发者工具导入各应用的 `dist/dev/mp-weixin`；正式构建输出在 `dist/build/mp-weixin`，H5 输出在 `dist/build/h5`。各端的 `touristappid` 是占位配置；在开发者工具导入页点击「测试号」，即可使用当前登录账号提供的测试 AppID。使用自己的小程序账号时，可在 `src/manifest.json` 的 `mp-weixin.appid` 配置对应 AppID。

若 Windows 微信开发者工具拒绝 WSL 的 `\\wsl.localhost\\...` 路径，可将编译产物持续同步到 Windows 本地目录：

```bash
python3 scripts/sync-weixin-preview.py \
  --target /mnt/c/Users/<Windows用户名>/WeChatProjects/StarIsle \
  --watch
```

然后导入该 Windows 目录中的 `user-miniapp` 和 `merchant-miniapp`。同步仅处理编译产物，保留开发者工具的私有配置；源配置仍为占位值时，也保留在 Windows 副本中填写的有效 AppID。开发时保持两个小程序的持续构建和同步命令运行；源码仍在本仓库中修改，Windows 目录用于编译预览。

`CI=true` 用于跳过 uni-app 编译器的联网更新检查。两端默认连接 `http://127.0.0.1:8787`。在微信开发者工具的本地设置中关闭合法域名、TLS 与 HTTPS 证书校验后编译；此配置仅用于本地模拟器。WSL 启动服务后可用 Windows PowerShell 的 `Invoke-RestMethod http://127.0.0.1:8787/health` 检查 localhost 转发。需要变更地址时，在两个应用的 `.env.local` 中设置相同的 `VITE_DEMO_API_BASE_URL`，然后重新构建。当前服务仅监听本机，不提供手机真机网络访问。

## 浏览器交互回归

首次准备浏览器：

```bash
./scripts/npm.sh exec -- playwright install --with-deps chromium
```

构建 H5 后执行：

```bash
./scripts/npm.sh run test:demo
CI=true ./scripts/npm.sh run build:h5
./scripts/npm.sh run test:e2e
```

Playwright 自动启动并关闭使用隔离测试数据的模拟服务（8787）和本地静态服务器（4173、4174），验证主要交互并保存截图到 `.tools/previews/`，报告在 `.tools/playwright-report/`。运行浏览器测试前先停止日常使用的 8787 服务；测试数据位于 `.tools/test-demo/marketplace.json`，不会读取日常演示数据。依赖已在系统或项目内可用时直接执行测试即可；若浏览器安装到自定义目录，运行时同时设置 `PLAYWRIGHT_BROWSERS_PATH`。

GitHub Actions 包含类型检查、模拟服务测试、两端构建和浏览器回归；原有后端集成测试继续保留。

## 工程结构

```text
apps/user-miniapp/      统一小程序入口，包含用户页面及商家工作台
apps/merchant-miniapp/  兼容原商家预览项目的完整构建目标
packages/ui/           共用图标、导航、弹层和主题
packages/shared/       接口类型、原有请求封装、本地演示数据及状态操作
backend/               已有 Java 21 + Spring Boot 4.1.2 后端骨架
scripts/               本地联动模拟服务、环境、构建和素材工具
compose.yaml           已有 MySQL 8.4 / Redis 8.2 开发环境
```

小程序编译要求 Vue 组件位于应用源目录内。`scripts/prepare-miniapp.mjs` 在 Vite 配置加载时同步共享组件、用户页面组件和商家组件到各目标忽略提交的 `src/generated/`。用户页面组件维护于 `apps/user-miniapp/src/components`，商家工作台与商品编辑器维护于 `apps/merchant-miniapp/src/components`；共享组件维护于 `packages/ui/src`，改动后重启构建以更新两个预览目标。

样板使用 uni-app + Vue 3 + TypeScript，工作区由 npm workspaces 管理。UI 素材位于各应用 `src/static/`；实际组件和交互使用代码实现。

## 工具链及已有后端

Linux x86_64 / WSL2 可选安装项目内 Node.js 22.23.4 与 Temurin JDK 21：

```bash
bash scripts/bootstrap.sh
```

工具缓存位于忽略提交的 `.tools/`，不会修改系统 shell 配置。应用端演示无需启动下列后端服务；需要查看已有接口时再执行：

```bash
python3 scripts/init-env.py
docker compose up -d --wait
./scripts/mvn.sh spring-boot:run
```

后端商品接口为 `http://127.0.0.1:8080/api/v1/products`，健康检查为 `/actuator/health`，本地开启的 Swagger UI 为 `/swagger-ui/index.html`。MySQL、Redis 默认端口分别为 13306、26379，本地随机密码保存在 `.env`。后端验证命令为 `./scripts/mvn.sh verify`，通过 Testcontainers 使用隔离数据库。

Docker Desktop 用户需启用当前发行版的 WSL Integration。停止本项目依赖使用 `docker compose stop`；不要提交 `.env`、第三方密钥或工具缓存。

## Spring Boot 双端联调

启动 MySQL、Redis 和 Spring Boot，在本地联调配置下运行两个预览端。用户 `13800000000` 和商家 `13800000009` 由后端初始化，选择身份后可一键登录。

```bash
docker compose up -d --wait
SPRING_PROFILES_ACTIVE=local-demo ./scripts/mvn.sh spring-boot:run

# 分别在两个终端运行，浏览器使用 localhost:5173 和 localhost:5174
CI=true VITE_MARKETPLACE_BACKEND=spring ./scripts/npm.sh run dev:user:h5
CI=true VITE_MARKETPLACE_BACKEND=spring ./scripts/npm.sh run dev:merchant:h5
```

微信开发者工具可使用相同环境变量运行 `dev:user` 和 `dev:merchant`。后端地址默认为 `http://127.0.0.1:8080`，可通过 `VITE_SPRING_API_BASE_URL` 修改。Spring Boot 联调覆盖商品发布、编辑和上下架、购物车结算、模拟支付、扣减库存、发货和确认收货。修改价格或资料时保留实时库存，主动调整库存时校验编辑前的库存。

毕设交付范围统一采用模拟交易。点击「模拟支付」后，Spring Boot 校验价格和库存并创建待发货订单。支付和退款仅改变系统的订单及库存记录，不调用微信支付，不产生扣款或资金划转。

Spring Boot 保存买家收货地址及默认地址。同一账号在不同设备登录后共享地址簿，首次同步会导入该设备在 Spring Boot 模式保存的旧地址。结算使用选中的地址，生成订单后保留原收货快照。

收藏由 Spring Boot 按买家账号保存，在商品卡片、商品详情和「我的收藏」同步。首次同步会导入设备在 Spring Boot 模式保存的旧收藏。下架商品从收藏列表隐藏，重新上架后恢复显示。

Spring Boot 购物车按账号同步商品、数量及勾选状态。首次同步会导入旧设备仍可识别的商品规格。下架和库存变化会提示调整，另一端修改购物车后需要重新确认结算。购物车模拟支付成功时，同步移除本次结算商品，保留其他商品。支付响应中断时，可以从购物车继续确认结果。

商家可在工作台和「我的小店」编辑店名与简介。营业店铺的新资料会同步显示在用户端的搜索结果和店铺页，新订单记录下单时的店名。

Spring Boot 版支持整单仅退款和退货退款。待发货订单获批后回补原规格库存，已发货订单的仅退款只冲减销量，退货退款由商家确认收货时选择是否回补库存。撤销和驳回会恢复原订单状态，保留历史售后记录。退款为模拟操作。

确认收货后，买家可按订单明细发布星级、文字和最多 3 张图片，商家可回复本店评价。商品详情展示评分和脱敏昵称。退款保留已发布的评价，并标记交易已退款。

商家可上传最多 6 张 JPG、PNG 或 WebP 静态图片，每张不超过 2 MB。图片经后端处理后保存在 `.tools/spring-uploads/`，可通过 `STARISLE_PRODUCT_IMAGE_DIR` 修改路径。MySQL 保存图片归属和商品引用。历史订单保留成交时的商品图片、价格和规格。

商品可附加一个 MP4（H.264）视频，最长 60 秒、最大 20 MB。商家可在商品编辑器中预览、更换或移除，买家在详情页按需播放。服务校验格式、时长和店铺归属，支持 HTTP Range 分段读取。视频保存在 `.tools/spring-videos/`，可通过 `STARISLE_PRODUCT_VIDEO_DIR` 修改路径，第一张图片仍作为封面。

如果 Windows 无法访问 WSL 内的 Java 服务，可在启动 Spring Boot 时加上 `JAVA_TOOL_OPTIONS=-Djava.net.preferIPv4Stack=true`，让 WSL 将 IPv4 环回端口转发给 Windows。

## 开发规划

当前先推进用户和商家流程，画师、漫展方保留入口但暂未开放。Spring Boot 联调已覆盖交易、售后、评价及商品视频。管理员界面当前隐藏，已实现店铺审核 API。

具体页面、两人分工和验收条件见 [应用端开发规划](docs/development-plan.md)。已有后端与长期模块约定见 [架构说明](docs/architecture.md)。
